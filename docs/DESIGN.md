# Design

## Goal
One Control4 driver for the Roku Streambar (soundbar + Roku player in one box) that
replaces the stock Roku driver plus room programming. The stock Snap One Roku
driver (v151) controls the Roku UI fine but ramps volume with
`keydown/VolumeUp` … `keyup/VolumeUp`, which the Streambar ignores, so holding
volume did nothing.

## Proxies
| Binding | Proxy | Name in Composer | Role |
|---|---|---|---|
| 5001 | `receiver` (primary) | Roku Streambar | Power, volume, mute; room audio end-point; HDMI Out to the TV |
| 5002 | `media_player` | Roku | The Roku UI as a source; navigation and transport |
| 5003 | `avswitch` | Roku App Switcher | Hidden in all rooms; App 1–25 inputs for app mini-drivers |

No `<combo>` tag (see CHANGELOG v0.1.5).

## Command handling (driver.lua)
### Receiver (5001)
| Command | ECP |
|---|---|
| ON | `keypress/PowerOn` (debounced 3 s), then `keypress/Home` after 2 s if On Power On = Home |
| OFF | `keypress/Home` then `keypress/PowerOff` 500 ms later if On Power Off = Home, else PowerOff |
| PULSE_VOL_UP / DOWN | `keypress/VolumeUp` / `VolumeDown` |
| START_VOL_UP / DOWN | repeating timer (Ramp Interval, default 150 ms) sending `keypress/Volume…`; a tick is skipped while the previous request is in flight; no immediate step (the PULSE already sent it) |
| STOP_VOL_UP / DOWN | cancel the timer; Max Ramp Time (10 s) is a safety stop |
| MUTE_TOGGLE / MUTE_ON / MUTE_OFF | `keypress/VolumeMute` (ECP has only a toggle) |
| SET_INPUT, CONNECT/DISCONNECT_OUTPUT, GET_IS_MUTED, END_VOL_* | no-op |

### Media player (5002)
| Command | ECP |
|---|---|
| UP / DOWN / LEFT / RIGHT | `keypress/<dir>` |
| START_<dir> / STOP_<dir> | `keydown/<dir>` / `keyup/<dir>` (native Roku repeat; works on the Streambar) |
| ENTER | `keypress/Select` |
| PLAY / PAUSE / PLAYPAUSE / STOP | `keypress/Play` |
| SCAN_* / SKIP_* | `keypress/Fwd` / `Rev`; START_/STOP_SCAN_* → keydown/keyup |
| HOME, BACK, REPLAY, OPTIONS | Home, Back, InstantReplay, Info |
| NUMBER_0–9 | `keypress/Lit_0`–`Lit_9` |
| MENU, GUIDE, INFO, CANCEL, RECALL, PVR, STAR, POUND | key chosen in the matching *… Button* property |
| ON/OFF, SELECT_SOURCE, WATCH_BUTTON, LISTEN_BUTTON, END_* | no-op |

### App switcher (5003)
- `SET_INPUT` with INPUT 3101–3125: find the mini-driver proxy bound to that input
  (`C4:GetBoundConsumerDevices` on binding 5003 → `C4:GetBoundProviderDevice`),
  then its protocol device (binding 5001 of the mini-driver), read device
  variable `UM_ROKU` (fallback `APP_ID`) and POST `launch/<appId>`.
- Passthrough Mode = Off: 500 ms later, rooms whose current source (room variable
  1000) is that mini-driver are sent `SELECT_VIDEO_DEVICE` with the Roku media
  player proxy id.
- `PASSTHROUGH` (from any binding): the wrapped `PASSTHROUGH_COMMAND` is handled
  as a navigation command, else as a receiver command.

## Discovery
- UDP binding 6100, `C4:CreateNetworkConnection(6100, "239.255.255.250")`,
  `C4:NetConnect(6100, 1900, "UDP")`; on ONLINE send
  `M-SEARCH * HTTP/1.1 / HOST / MAN "ssdp:discover" / MX 3 / ST roku:ecp`.
- Responses (`ReceivedFromNetwork`) are parsed for `LOCATION: http://<ip>:8060/`
  and `USN: uuid:roku:ecp:<serial>`; each new serial gets a
  `query/device-info` for name and model.
- Roku Player Selector entries are `"<name or model> [<serial>]"`; selection stores
  the serial in `PersistData.selectedSerial`.
- Address used for commands: Roku IP if set, else the last SSDP IP of the
  selected serial.

## Status/feedback
- Connection Status / Device from `query/device-info` (power-mode, model,
  software-version).
- Current App from `query/active-app`, every Polling Time seconds and 2–3 s after
  Home/Back/app launch.
- No volume level or mute state: ECP has no endpoint for either.

## Provenance / licensing
All code and XML here are written for this project. The stock Snap One Roku driver
(v151, plain-text Lua) and Snap One's public DriverWorks documentation were read
as references for the proxy architecture, connection conventions and the
universal mini-driver mechanism, but no Snap One code was copied. This matters
because Snap One's `drivers-common-public` license assigns any *derivative work*
of their code to Snap One — a driver built on their code could not be owned or
sold by Final Touch AV.
